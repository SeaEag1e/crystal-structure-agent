# 面试准备文档：Crystal Structure Agent

> 本文档面向"AI 智能体研发工程师"岗位面试，涵盖项目全链路技术细节、部署流程、JD 对标分析和高频面试问答。

---

## 一、项目一句话概述

**一个基于 LangGraph 多智能体架构的晶体结构预测平台**——用自然语言驱动"扩散模型生成 → M3GNet 形成能打分 → spglib 对称分析 → 实验结构对比"全链路，通过 Streamlit Web 应用对外提供交互式服务。

---

## 二、项目背景与动机

### 2.1 科研痛点

我从事能源化工领域的层状磷酸卤化物（MPX₃I 族，如 GaPSe₃I）的计算筛选。完整科研流程是：

```
化学式输入 → 候选结构生成 → 稳定性评估 → 对称性分析 → 与实验对比 → TOP候选筛选
```

过去每筛一个化学式需要手工拼接 5-6 个脚本、半天时间。我的目标是把这个流程封装成一个智能体系统：用户只需说"找出最稳定的结构并分析它们的对称性"，Agent 自动规划工具链、执行、汇总报告。

### 2.2 技术挑战

- **扩散模型需要 GPU**：在线免费 CPU 环境跑不了 DiffCSP++
- **LLM 输出不稳定**：JSON 格式可能损坏、意图可能分类错误
- **免费部署资源有限**：HF Spaces 免费 2vCPU / 16GB
- **多工具链式调用**：上游工具输出是 dict，下游工具需要 path，类型不匹配

## 三、技术架构（对标 JD 关键词）

### 3.1 系统分层

```
┌─────────────────────────────────────────────────┐
│                Streamlit UI 层                    │
│  首页(自检) │ Agent对话 │ 结构库浏览 │ GPU生成   │
├─────────────────────────────────────────────────┤
│              LangGraph Agent 层                    │
│  Intent Node → Planner Node → Executor (loop)     │
│                                    → Summarizer   │
├─────────────────────────────────────────────────┤
│              工具层 (6个 @tool)                    │
│  query_library │ score │ symmetry │ filter │      │
│  compare_experiment │ generate_gpu               │
├─────────────────────────────────────────────────┤
│              Core 核心库 (纯函数)                  │
│  structures.py │ scoring.py │ symmetry.py │      │
│  generation.py                                    │
├─────────────────────────────────────────────────┤
│              Data 知识库层                         │
│  index.csv (186结构) │ CIF文件 │ M3GNet权重      │
└─────────────────────────────────────────────────┘
```

### 3.2 LangGraph Agent 拓扑

**四节点 + 条件边循环**，纯 `StateGraph` 五件套 API（`add_node` / `add_edge` / `add_conditional_edges` / `END`），钉版本 `langgraph>=0.2.60,<2`，不依赖 prebuilt：

```
START → intent_node → planner_node → executor_node ─(cursor<len)→ executor_node
                                            └─(done)→ summarizer_node → END
```

| 节点 | 对标 JD | 功能 | Fallback |
|------|---------|------|----------|
| intent_node | 意图识别模块 | LLM 输出 JSON `{intent, formula}` + 正则抽取 | 规则关键词匹配（7类意图） |
| planner_node | 任务规划引擎 | LLM 输出 plan JSON + 白名单校验 | 规则链式规划（组合意图→多步链） |
| executor_node | 多 Agent 协同调度 | 按 plan[cursor] 逐步调用 TOOL_MAP | 异常结果标记为失败，不中断链 |
| summarizer_node | 性能优化 | LLM 生成 Markdown 报告 | 规则模板输出表格/JSON |

**关键设计——Supervisor 模式**：Planner Agent（规划）+ Executor Agent（调度执行）+ Analyst Agent（汇总解读）三角色共享 AgentState 协作。

### 3.3 六个工具

| 工具名 | 签名 | 实现核心 |
|--------|------|----------|
| `query_structure_library` | `(formula="", limit=8) -> list[dict]` | 读预计算 index.csv |
| `score_structures` | `(cif_paths: list) -> list[dict]` | M3GNet 形成能预测（兼容 str 和 dict 输入） |
| `analyze_symmetry` | `(cif_paths: list, symprec=0.1) -> list[dict]` | spglib 空间群 + 极性判断 |
| `filter_stable` | `(candidates, threshold=0.0, top_k=10) -> list[dict]` | 形成能升序 + 每化学式≤2个 |
| `compare_with_experiment` | `(cif_paths) -> dict` | 晶格偏差% / 体积差 / 实验参照 |
| `generate_local_gpu` | `(formula, num=3) -> dict` | DiffCSP++ 生成；无GPU时优雅降级 |

### 3.4 M3GNet 打分的三级降级链

```
Level 1: matgl.load_model(本地权重) → 精确形成能预测
   ↓ 失败
Level 2: matgl.load_model(HF在线) → 在线权重预测
   ↓ 失败
Level 3: 元素焓值启发式估算 → 粗略稳定性排序
   ↓ 失败
Level 4: 返回 method="failed" → 不中断，标记不可用
```

## 七、高频面试问答

### Q1: 为什么选 LangGraph 而不是 LangChain Agent Executor 或 AutoGen？

**答**：LangGraph 的优势在于显式状态管理。`AgentState` TypedDict 让每一步的输入输出类型清晰可查，条件边循环（executor_node → executor_node）用 `cursor < len(plan)` 控制，比 Agent Executor 的黑盒 ReAct 循环更可控。此外，我钉了 `langgraph>=0.2.60,<2` 只用五件套经典 API（`add_node` / `add_edge` / `add_conditional_edges` / `END`），不依赖 prebuilt，避免 API 变动风险。AutoGen 更适合多 Agent 对话场景，而本项目是单 Agent 工具链调度，LangGraph 更轻量。

### Q2: 如果 LLM 返回的 JSON 损坏了怎么办？

**答**：每个 LLM 边界都有三层防御：
1. **Prompt 层**：明确要求输出 JSON 格式
2. **解析层**：`json.loads()` 失败后用正则抽取关键字段（如化学式 `\b[A-Z][a-z]?\d*...`）
3. **兜底层**：正则也失败时走规则函数（`_rule_intent` 关键词匹配 7 类意图 / `_rule_plan` 组合链式规划）

所以即使断网、API key 错误、LLM 返回乱码，系统仍然完全可用——smoke test 验证了 3 条链路 0 失败。

### Q3: 在线免费 CPU 环境跑不了 DiffCSP++ 怎么办？

**答**：这是设计亮点而非缺陷。我的策略是"预计算 + 实时混合架构"：
- **预计算**：用 `export_library.py` 在本地 GPU 上跑完 DiffCSP++ 生成 186 个结构，结果存入 `index.csv` 知识库
- **实时**：在线 CPU 只跑 M3GNet 打分（模型仅 2.3MB），用户可对任何结构重新打分
- **降级**：`generate_local_gpu` 工具在调用时检查 CUDA，不可用时返回 `{"available": False, "reason": "..."}`，Agent 在汇总报告中告知用户原因，而不是抛异常

这对应了 JD 中"智能体调度与性能优化"——Agent 能感知自身运行环境的能力边界。

### Q4: 工具之间怎么传递数据？类型不匹配怎么办？

**答**：这是个实际遇到的问题。`query_structure_library` 返回 `list[dict]`（含 cif_path 字段），但 `analyze_symmetry` 原来签名要求 `list[str]`。修复方案：
1. 工具签名放宽为 `list`（兼容 str 和 dict）
2. 添加 `_as_cif_path(item)` 辅助函数：如果是 dict 就取 `"cif_path"` 字段，如果是 str 直接用
3. Executor 支持引用语法 `{"$from": "query_structure_library"}`：把上游工具的输出列表传给下游

### Q5: 你怎么保证在线 Demo 的性能？

**答**：四个层面的优化：
- **模型缓存**：`st.cache_resource` 让 M3GNet 模型只加载一次，后续请求复用
- **数据缓存**：`st.cache_data` 缓存 `load_index()` 和单结构对称分析结果
- **线程控制**：`torch.set_num_threads(2)` 适配 2-vCPU 的免费 Spaces
- **推理模式**：`torch.inference_mode()` 关闭梯度计算

### Q6: 项目中有哪些降级策略？

**答**：共五层降级：

| 层 | 正常路径 | 降级路径 |
|----|---------|---------|
| LLM 可用性 | GLM-4-Flash 意图识别 | 规则关键词匹配 |
| LLM JSON | json.loads 解析 | 正则抽取 |
| 计划生成 | LLM 规划工具链 | 规则组合链式规划 |
| M3GNet 权重 | 本地权重加载 | HF 在线 → 焓值估算 → 标记 failed |
| GPU 可用性 | DiffCSP++ 实时生成 | 返回降级 dict + 预计算库 |

### Q7: 你在项目中遇到过什么技术困难？怎么解决的？

**答**：举两个例子：

**困难一：工具间类型不匹配**。上游 `query_structure_library` 返回 `list[dict]`，下游 `analyze_symmetry` 期望 `list[str]`，导致 Agent 执行链中断。解决方案是统一用 `_as_cif_path()` 做类型归一化，工具签名从 `list[str]` 放宽为 `list`。

**困难二：.gitignore 误杀模型权重**。`*.pt` 规则把内嵌的 M3GNet 权重也排除了，导致 HF Spaces 部署后打分功能不可用。解决方案是加白名单例外 `!data/models/matgl/**/*.pt`。

1. **首页**（30秒）：展示架构图 + 三绿点环境自检，说"M3GNet 已加载，API Key 就绪，GPU 不可用但已优雅降级"

2. **Agent Chat**（2分钟）：
   - 输入"找出最稳定的结构并分析它们的对称性"
   - 展开 st.status 折叠面板，指着说：
     - "看，意图识别出了 stability + symmetry 复合意图"
     - "规划引擎生成了 3 步链式计划：query → filter → symmetry"
     - "Executor 逐步执行，每步都引用上一步的输出"
   - 展示最终 Markdown 报告

3. **结构库**（2分钟）：
   - 筛选 GaPS3I，展示 3D 球棍模型（stmol + py3Dmol 渲染）
   - 点击"重新打分"，展示 M3GNet 实时预测形成能
   - 说："这就是 CPU 环境的实时打分能力"

4. **GPU 模式**（30秒）：
   - 打开页面展示降级说明
   - 说："Agent 在工具层就感知到 GPU 不可用，返回降级提示而不是报错。本地有 GPU 时这里就是完整 DiffCSP++ 1000 步扩散采样"

### 8.2 可能被追问的问题

- "为什么用规则兜底而不是用 GPT-4？" → 免费 + 稳定 + 可离线，符合工业部署需求
- "index.csv 有 186 条，规模太小了吧？" → 这是预计算库，M3GNet 可对任意用户上传 CIF 实时打分，知识库只是种子数据
- "多 Agent 在哪里？" → Supervisor 模式，Planner / Executor / Summarizer 三角色共享 State；Roadmap 里有 Multi-agent debate 规划
- "分布式在哪里？" → 本地 GPU 生成 + 在线 CPU 打分的混合架构，是分布式计算的模式；异步并行打分在 Roadmap

## 十、技术栈一览

| 层 | 技术 | 版本 |
|----|------|------|
| Agent 框架 | LangGraph | >=0.2.60, <2 |
